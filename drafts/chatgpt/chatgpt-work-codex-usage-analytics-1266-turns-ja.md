ChatGPT WorkとCodexをかなり激しく使った後、アナリティクスを確認して驚きました。

直近1か月のターン数は==1,266回==。しかも、短い質問への回答だけではありません。長文や多数の資料の解析、Web調査、複数ファイルの生成、コード実行、GitHubや外部サービスの操作、公開フローまで含む、明らかに重いエージェント作業を繰り返しています。

ところが、画面に表示されていたのは「週間利用上限 92%残り」でした。追加クレジットの残高は0で、クレジット利用履歴も0件です。

:::conclusion
1か月で1,266ターン使っていても、確認時点の週間枠は92%残っていました。ターン数だけを見て「もう上限に近い」と判断することはできません。
:::

## 最初は「92%使った」と読み間違えた

使用量画面には、大きく「92%」と表示されます。そのため、一瞬「さすがに使いすぎて、週間枠を92%消費したのか」と思いました。

しかし、表示は「92%残り」です。つまり、その時点で使っていたのは週間枠の約8%でした。

同じ画面には次の情報もありました。

| 項目 | 確認時の表示 |
| --- | --- |
| プラン | ChatGPT Plus |
| 集計期間 | 直近1か月 |
| ターン数 | 1,266 |
| 週間利用上限 | 92%残り |
| 追加クレジット | 0 |
| クレジット利用履歴 | 0件 |
| 主なモデル | GPT-5.6 Luna、Sol、Sol-WM、Terra |
| 主な利用面 | Desktop App、CLI、Web、Mobile |

かなり使った実感と、残量表示の間に大きな差があります。

## WorkとCodexは同じ利用枠

OpenAIの公式料金ページでは、ChatGPT WorkとCodexは同じ料金、クレジット、使用上限を共有すると明記されています。

つまり、ChatGPTアプリ内のWorkでエージェントに仕事を任せても、Codexのデスクトップアプリ、CLI、IDE、クラウドを使っても、基本的には同じ財布から消費されます。

:::note
通常のChatGPT会話のすべてが同じ枠という意味ではありません。ここで共有されるのは、WorkとCodexのエージェント作業に関する利用枠です。
:::

## 1,266ターンと92%残りが両立する理由

この二つの数字は、単純には比較できません。

### 集計期間が違う

1,266ターンは7月24日から8月22日までの約1か月分でした。一方、92%残りは現在の週間利用枠です。

1か月の間には、すでにリセットされた週の利用も含まれています。過去1か月の総ターン数が多くても、現在の週間残量が多いことは不思議ではありません。

### 1ターンの重さが一定ではない

利用量は「メッセージを1回送ったら1ポイント」のようには数えられません。公式説明では、利用できるメッセージ数はモデル、タスクの規模と複雑さ、ローカル実行かクラウド実行かなどによって変わります。

同じ1ターンでも、短い応答と、長い文脈を保持しながら多数のファイルを処理する作業では消費量が異なります。

### モデルによって利用効率が違う

GPT-5.6 Lunaは軽量・大量処理向けで、Terraは日常的な実務向け、Solは難しい推論や複雑な作業向けです。

今回は複数のモデルを使っていました。すべてを最重量モデルだけで処理したわけではないため、ターン数に比べて週間枠の消費が抑えられた可能性があります。

## ただし「今週あと12倍使える」とは限らない

92%残りなら、単純計算で現在までの約12倍使えそうに見えます。しかし、これは保証されません。

- 今後使うモデルが違う
- ファイルや会話履歴が大きくなる
- 長時間のクラウド作業が増える
- 画像生成など消費の大きい機能を使う
- 5時間枠や追加の週間制限が別に作用する

といった条件で、減り方は変わります。

:::warning
ターン数と残量から、正確な残り作業回数を逆算することはできません。使用量はモデル、トークン、文脈、推論、ツールなどによって加重されます。
:::

## それでもPlusのコストパフォーマンスはかなり高い

今回の使い方は、単なるチャットではありません。内容を特定できないよう一般化しますが、たとえば次のような作業を継続的に実行しています。

- 大量の資料を読み、比較・検証する
- 長文の下書きを作り、修正を重ねる
- Webで最新情報を調査する
- 複数形式のファイルを生成する
- コードを実行し、結果を確認する
- GitHubでファイル、ブランチ、Pull Requestを扱う
- 外部サービスと連携する
- 下書きから公開までの工程をつなぐ
- デスクトップ、Web、モバイル、CLIを横断する

人間が画面を直接操作する代わりに、「何を完成させるか」を伝えて工程ごと任せる使い方です。これだけの作業を行いながら、確認時点では週間枠の92%が残っていました。

もちろん、上限は固定のターン数ではなく、同じPlusユーザーでも使い方によって結果は変わります。それでも、WorkとCodexを実務のエージェントとして使う場合、Plusの利用枠は想像よりかなり大きい可能性があります。

## 残量はアナリティクスで確認できる

Codexのアナリティクス画面では、次の項目を確認できます。

- 週間利用上限の残量
- リセット予定時刻
- 追加クレジット
- Desktop App、CLI、Web、Mobileごとの利用状況
- モデル別のターン数
- プラグイン呼び出し
- 使用したスキル

「最近かなり使ったから、そろそろ止まるかもしれない」と感じたら、体感ではなく残量表示を見るのが確実です。

CLIを使っている場合は、セッション中に `/status` でも残量を確認できます。

## まとめ

WorkとCodexの利用枠は別々ではなく、共有されています。それにもかかわらず、今回の実測では、約1か月に1,266ターン、重いエージェント作業を含む利用を続けても、確認時点の週間枠は92%残っていました。

重要なのは、ターン数とクォータ消費量が一致しないこと、そして1か月のターン数と現在の週間残量は集計期間が異なることです。

:::conclusion
「めちゃくちゃ使った」という体感だけでは、残量は分かりません。WorkとCodexを本格的に使っていても意外に余裕がある場合があるため、まずアナリティクスを確認するのがおすすめです。
:::
