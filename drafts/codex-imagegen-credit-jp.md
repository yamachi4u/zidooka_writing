Codexで画像を生成すると、クレジット（使用量）をどれくらい消費するのか。公式ドキュメントを調べてまとめました。

## 「クレジットって何？」

Codexの世界で言う**クレジット**とは、OpenAIのChatGPTプランにおける「使用量の単位」です。

イメージとしては**スマホのデータ通信量**に近いです。月額プランに入っていると一定量のデータが使えて、使い切ったら速度制限になるか追加チャージが必要——あれと同じです。

- **Plus（$20/月）**: 5時間ごとに決まった数のメッセージが使える
- **Pro（$100/月）**: Plusの5倍の使用量
- **使い切ったら**: 追加クレジットを購入するか、リセットを待つか、小さいモデルに切り替える

クレジットは5時間ごとにリセットされ、モデルや機能によって消費量が変わります。**GPT-5.4-mini**は軽い（1回〜2クレジット）、**Fast mode**は重い（2倍消費）、**画像生成**はこの記事で調べているポイントです。

ちなみに、最近のBusinessプランではトークン単位の課金に移行しつつありますが、Plus/Proでは「1メッセージ = 約○クレジット」というざっくりした枠組みが続いています。この記事の数字はそのPlus/Proのクレジット表記です。

## 結論

**画像生成1回（1024×1024）は約5〜6クレジット。**

通常のテキストメッセージ1回が約7クレジット（Plus/Proの場合）なので、画像のほうが若干クレジット消費は少ないです。

## クレジット消費の比較

| 項目 | 消費クレジット（Plus/Pro） |
|------|--------------------------|
| テキストメッセージ1回（GPT-5.4） | ~7 credits |
| 画像生成 1024×1024 | ~5-6 credits |
| 画像生成 1024×1536 | ~7-8 credits |
| Cloud task（GPT-5.3-Codex） | ~25 credits |
| Fast mode（2倍消費） | 通常の2倍 |

画像生成は「テキストより重い」と思われがちですが、単純な比較だと画像のほうがクレジット消費は少ないです。ただし、サイズを大きくしたり品質を上げると最大3〜5倍まで跳ね上がります。

## imagegenスキル自体のトークン消費

多くの人が気にするのが「スキルを入れておくとコンテキストを圧迫するのでは？」という点。

Codexのスキルは **progressive disclosure** という仕組みで動いています。

| 状態 | コンテキスト負荷 |
|------|----------------|
| スキルを使わない | スキル名＋説明のみ（全スキル合計8,000文字以内） |
| スキルを使うとき | 初めてSKILL.md（24KB）＋参照ファイル（~30KB）がフルロード |

つまり、**imagegenを実際に呼ばなければ、スキルがコンテキストを圧迫することはほぼありません。**

## 「APIを横取りしてる？」→ 違います

Codexのビルトインimagegenは、OpenAIのResponses APIの `image_generation` ツールをネイティブで呼び出しているだけです。ユーザーのAPIキーは不要で、ChatGPTプランの枠内で動作します。

```
あなたのプロンプト
  → GPT-5.5がリライト（プロンプト最適化）
  → 内部のgpt-image-2が画像生成
  → base64で結果が返ってくる
```

## CLIフォールバックは別物

| 方式 | 課金元 | 特徴 |
|------|--------|------|
| ビルトイン `image_gen` ツール | ChatGPTプランのcredits | 3〜5倍レート、APIキー不要 |
| CLIフォールバック（scripts/image_gen.py） | OpenAI APIキー | 画像APIの従量課金、別料金 |

CLIフォールバックを使うと、APIキー経由で別途課金が発生します。Codexのレートリミットとは独立した課金体系です。

:::conclusion
Codexのimagegenは「テキストより重い」どころか「テキストと同程度かやや軽い」クレジット消費です。スキル自体のコンテキスト負荷もprogressive disclosureで最小限に抑えられています。AIに「画像作って」と気軽に頼んで大丈夫、というのが実態です。
:::
