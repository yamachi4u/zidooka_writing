## はじめに

Codex CLI を使っていると、以下のような状況に遭遇することがあります。

- 応答が急に遅くなった
- 「重い」と感じる
- レート制限（rate limit）のエラーが出る
- トークン消費が激しい

この記事では Codex CLI のパフォーマンス低下・レート制限の原因と、実務で使える対処法をまとめます。

:::conclusion
レート制限は「5時間ごとのリセット」または「週間リセット」の2種類が存在します。`codex status` で現在の使用状況を確認し、モデルを切り替えるか時間をおくことで回避できます。
:::

## 原因別の対処法

### 1. レート制限（rate limit）に達している

**エラーメッセージ例**:
- `user_global_rate_limited:free`
- `user_global_rate_limited:pro`
- `sorry, you have been rate-limited`

**対処法**:
- `codex status` を実行して現在の使用量とリセット時間を確認
- 5時間セッション制限の場合は時間をおく
- 週間制限の場合は翌週まで待つか、Pro プランにアップグレード

### 2. トークン消費が大きい

現在のモデルが大規模なコンテキストを処理している可能性があります。

**対処法**:
- `codex status --verbose` でトークン消費量を確認
- CLAUDE OPUS 4.5 など高消費モデルから HAIM 等の軽量モデルに切り替え
- `.codex/config.toml` でデフォルトモデルを変更

### 3. ネットワーク遅延

Codex CLI はクラウド上のモデルと通信するため、ネットワーク状況に影響を受けます。

**対処法**:
- 大容量ファイルのダウンロード中でないか確認
- VPN を一時的にオフにして試す
- `codex chat --model haiku` など軽量モデルで応答速度を確認

### 4. クライアント側の負荷

ローカルマシンのリソース不足が原因の場合もあります。

**対処法**:
- ブラウザのタブを減らす
- 他の重いアプリケーションを終了
- `codex` を再起動

## 実務でのテクニック

### モデルを使い分ける

| 状況 | 推奨モデル |
|------|-----------|
| 簡単なコード生成 | HAIM または GPT-4.1 |
| 複雑なリファクタリング | CLAUDE SONNET 4.6 |
| 大規模なアーキテクチャ設計 | CLAUDE OPUS 4.5 |
| ちょっとした質問 | GPT-4.1 mini |

### セッションを分割する

1つのセッションが長くなるとコンテキストが肥大化し、トークン消費と応答時間が増加します。タスクごとに新しいセッションを開始すると効率的です。

## まとめ

- レート制限は `codex status` で確認
- `codex status --verbose` で詳細なトークン消費を確認できる
- モデルの使い分けでトークン消費を最適化
- ネットワーク・ローカルリソースも要因になり得る
- 「重い」と感じたらまず軽量モデルに切り替えて原因切り分け
