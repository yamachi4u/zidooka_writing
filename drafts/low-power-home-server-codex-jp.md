省電力なミニPCを24時間動かして、自宅サーバにする。以前なら「面白いけれど、構築と保守が面倒」という話になりがちでした。

ところが、Codexのようなコーディングエージェントを使える現在は少し事情が違います。Ubuntu Serverを入れ、Docker Composeやsystemd、GitHub Actionsのself-hosted runnerなどを整える作業のかなりの部分をエージェントに任せられます。

一方で、そこまでやるなら「VPSを借りればよくない？」という話にもなります。

## N100/N150級なら常時稼働しやすい

Intel N100/N150級のミニPCは、軽量なLinuxサーバ用途では十分な性能があります。機種や設定によりますが、アイドル時の消費電力を一桁〜10W前後に抑えられる製品もあります。

仮に平均10W、電気料金を35円/kWhとして計算すると、年間消費電力量は約87.6kWh、電気代は約3,100円です。月額にすると約260円なので、電気代だけを見れば常時稼働のハードルは高くありません。

16GB RAMと500GB程度のSSDがあれば、Dockerコンテナ、軽量DB、定期バッチ、GitHub Actions runner、バックアップ処理など、かなり幅広く使えます。

## Codexがあると「構築が面倒」がかなり薄れる

自宅サーバで面倒なのは、ハードウェアそのものより環境構築と保守です。

Ubuntu Serverのセットアップ後にも、SSH、Docker、ファイアウォール、systemd、アップデート、バックアップ、ログ管理などが待っています。

しかし、エージェントがLinux環境を操作できるようにしておけば、設定ファイルの作成、Docker Compose化、障害調査、アップデート作業などをかなり任せられます。

構成も複雑にせず、たとえば次のようにしておくと扱いやすそうです。

`N100/N150ミニPC → Ubuntu Server → Docker Compose → GitHub → Codex`

設定をGit管理しておけば、マシンが壊れても、新しい環境へリポジトリをcloneして再構築しやすくなります。

つまり、自宅サーバというより「Codexが使える、自分専用の常時稼働Linux実行環境」を置くイメージです。

## で、VPSでよくない？

ここが最大の問題です。

Webアプリ、Bot、定期処理、軽いDBなどを動かすだけなら、VPSのほうが合理的な場合が多いでしょう。ハードウェア購入費が不要で、停電、自宅回線、ルーター、SSD故障などを気にする必要もありません。グローバルIP周辺の面倒も少なく、外部公開も容易です。

自宅に2〜3万円のミニPCを置く場合、電気代が安くても初期費用を回収するには時間がかかります。

:::conclusion
単に「安い常時稼働Linuxが欲しい」なら、まずVPSを検討したほうが簡単です。
:::

## それでも自宅サーバが面白いケース

自宅サーバにはVPSにはない用途があります。

大容量ストレージを安く持ちたい、NASを兼用したい、LAN内の機器を操作したい、GitHub ActionsのビルドマシンとしてCPUを好きなだけ回したい、ローカル専用サービスを置きたい、といった用途です。

また、月額課金ではなく「一度買った機械を好きに使える」という性質そのものに価値があります。実験環境としてDockerやネットワークを壊しても、自分の箱なので気兼ねがありません。

公開Webサーバ自体はCloudflareなどのクラウド側に置き、自宅機をCI/CD、バックアップ、バッチ処理、self-hosted runnerなどの裏方に限定する構成も扱いやすいでしょう。自宅回線へ直接ポートを公開しない設計にすれば、運用上のリスクも減らせます。

## 結局どうするか

以前なら、自宅サーバは「構築が好きな人向け」という側面が強かったと思います。しかしCodexなどにセットアップと保守を手伝わせられるなら、そのハードルはかなり下がります。

ただし、その結果として浮かび上がるのが「だったらVPSを借りればよくない？」という身も蓋もない結論です。

VPSで済む仕事はVPSへ。大容量ストレージ、LAN内処理、自由なビルド環境、ハードウェアそのものを使いたい仕事は自宅サーバへ。

N100/N150級の省電力ミニPCは、その境界線を試すにはなかなか面白い機械です。
