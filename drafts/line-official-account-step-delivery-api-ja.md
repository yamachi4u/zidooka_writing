# LINE公式アカウントの配信・ステップ配信はCodexから登録できるのか

LINE公式アカウントの運用作業をCodexに任せられないか調べた。特にやりたかったのは、配信文を作らせることではなく、「この日時にこの内容を配信する」「友だち追加から数日後にこのメッセージを送る」といった配信設定そのものを登録させることだった。

## 通常の予約配信

LINE Messaging APIでは、任意のタイミングでメッセージを送ることができる。全員への配信、特定ユーザーへの送信、条件を指定した配信などはAPIから実行できる。

一方、LINE公式アカウントの管理画面にある「予約配信」を、そのままAPI経由で登録する仕組みとして考えるより、自前で予約処理を持つ方が現実的である。

たとえば、配信日時と本文をデータベースなどに保存しておき、Cloudflare WorkersのCron TriggerやGitHub Actionsなどを指定時刻に動かし、Messaging APIを呼び出す。これならCodexに「8月25日19時にこの文章を全員へ配信」と指示して、予約データを登録させる仕組みを作れる。

つまり通常配信については、LINE公式アカウントの管理画面を自動操作する必要はなく、Messaging APIを中心に自前の予約配信機構を作ればかなり自動化できる。

## ステップ配信

問題はLINE公式アカウントの「ステップ配信」である。

LINE公式アカウントには、友だち追加などを起点として、一定期間後に順番にメッセージを送る純正のステップ配信機能がある。しかし、Messaging APIには、LINE公式アカウント側にあるステップ配信シナリオを作成・編集・削除するための公開APIが用意されていない。

そのため、LINE純正のステップ配信を利用する場合、シナリオの登録や編集は基本的にOfficial Account Managerの管理画面から手動で行う必要がある。CodexからAPIを叩いて純正ステップ配信を登録する、という運用にはできない。

## ステップ配信自体を自作することはできる

ただし、「ステップ配信という挙動」そのものはMessaging APIを使って自作できる。

たとえば、

- 友だち追加直後：登録のお礼
- 1日後：サービス説明
- 3日後：事例紹介
- 7日後：申込案内

というシナリオを自前のデータベースに保存する。友だち追加時のWebhookを起点としてユーザーごとの開始日時を記録し、定期実行処理が「誰に何通目を送る時刻か」を判定してMessaging APIから送信すればよい。

この方式なら、ステップ配信のシナリオ自体も自分たちのAPIで管理できるので、Codexに「新規友だちへ0日後、2日後、7日後のステップ配信を登録して」と指示する運用も可能になる。

## 結論

LINE純正機能をそのまま使う場合、通常のメッセージ送信はMessaging APIによる自動化の余地が大きいが、純正ステップ配信のシナリオ登録は管理画面での手動作業が残る。

ステップ配信の登録作業までCodexに任せたい場合は、LINE純正ステップ配信を使うのではなく、Messaging API＋Webhook＋データベース＋定期実行処理でステップ配信エンジンを自前実装するのがよい。

配信数やシナリオが少ないうちは純正ステップ配信を手動登録し、手作業が負担になってきた段階で自前実装へ移行するのが現実的だと思う。
