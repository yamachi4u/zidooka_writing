OpenCode Go の利用量ダッシュボードを見ていて、月間利用量のリセット表示が少し気になりました。

![OpenCode Go の利用量表示](C:/Users/user/Pictures/screenshots/スクリーンショット 2026-05-19 124727.png)

スクリーンショットでは、次のように表示されています。

- ローリング利用量: 3%、リセットまで 1時間21分
- 週間利用量: 1%、リセットまで 5日20時間
- 月間利用量: 49%、リセットまで 17日23時間
- 「利用限度額に達したら利用可能な残高を使用する」はオフ

:::conclusion
OpenCode Go には短期・週次・月次の3種類の利用制限があります。今回気になったのは、月間利用量そのものよりも、月次リセットまでの日数表示が体感よりかなりゆっくり進んで見える点です。
:::

## 何が気になったのか

ローリング利用量や週間利用量はかなり低く、現在すぐに詰まっている状態には見えません。

一方で、月間利用量は 49% と表示されています。数字自体は減っているように見えるものの、月次のリセット日数がしばらく「20日」のままだったり、体感として2日に1日くらいしか進んでいないように見えたりしました。

もちろん、これは単に表示更新のタイミング、契約サイクルの扱い、タイムゾーン、あるいは内部集計の仕様かもしれません。ただ、普通に「月間リセットまでの日数」として読むと、少し違和感があります。

## OpenCode Goの利用制限はどうなっている？

公式ドキュメントでは、OpenCode Go の利用制限は次の3つとして説明されています。

- 5時間制限: $12 相当の利用
- 週間制限: $30 相当の利用
- 月間制限: $60 相当の利用

また、利用制限は単純なリクエスト回数ではなく、ドル換算の使用量として定義されています。そのため、どのモデルを使うかによって、同じ操作回数でも消費の進み方は変わります。

参考:

- [OpenCode Go documentation](https://opencode.ai/docs/go/)

## 同じような報告はある？

今回の「月次リセットまでの日数が体感より遅く進む」という症状そのものに完全一致する報告は、確認した範囲では見つかりませんでした。

ただし、近い話はいくつかあります。

GitHub では、OpenCode Go の rolling、weekly、monthly の利用率とリセットタイマーをAPIで取得できるようにしてほしい、という feature request が出ています。これは、現在の利用量確認が基本的にWebダッシュボード頼みであることを示しています。

- [GitHub issue: Add Go plan usage/balance API endpoint](https://github.com/anomalyco/opencode/issues/16017)

Reddit では、OpenCode Go の月間リセットが「毎月1日」なのか「契約日から30日」なのかを質問する投稿があり、コメントでは「月間制限は契約サイクルに沿う」という説明がされています。

- [Reddit: Opencode billing reset](https://www.reddit.com/r/opencodeCLI/comments/1svfypn/opencode_billing_reset/)

また、rolling、weekly、monthly の3種類の制限が分かりにくい、週次と月次の両方があるとどちらが本当のボトルネックなのか分かりにくい、という趣旨の投稿もありました。

- [Reddit: Why does OpenCode Go have rolling, weekly, AND monthly limits?](https://www.reddit.com/r/opencodeCLI/comments/1t9d274/why_does_opencode_go_have_rolling_weekly_and/)

## 仕様か不具合かはまだ分からない

今回の表示だけで、OpenCode Go 側の不具合だと断定はできません。

考えられる可能性としては、次のようなものがあります。

1. 月次リセットがカレンダー月ではなく契約サイクル基準になっている
2. 表示がリアルタイム更新ではなく、一定間隔で再計算されている
3. タイムゾーンの違いで、ユーザーの体感日数と表示がずれている
4. 月間利用量のパーセンテージと「リセットまで」の計算基準が別になっている
5. 単純にダッシュボード表示の更新が遅れている

現時点では、「月次利用量が減っていない」というより、「月次リセットまでの日数表示の進み方が直感と合わない」という見方が近そうです。

## 確認するならスクショを残す

同じ症状を追うなら、数日おきにスクリーンショットを残しておくのがよさそうです。

記録しておきたいのは次の項目です。

- 撮影日時
- ローリング利用量とリセットまでの時間
- 週間利用量とリセットまでの時間
- 月間利用量とリセットまでの日数
- その間にOpenCode Goをどの程度使ったか
- 使用した主なモデル

これを数日分並べれば、月次リセット表示が本当に遅れているのか、あるいは契約サイクルや表示更新の仕様なのかを判断しやすくなります。

## まとめ

OpenCode Go のスクリーンショットでは、ローリング 3%、週間 1% に対して、月間利用量は 49%、リセットまで 17日23時間と表示されていました。

月間利用量の数字自体は少しずつ変わっているように見えます。ただ、リセットまでの日数がしばらく同じに見えたり、体感より遅く進んだりする場合は、通常の月次カウントダウンとしては少し分かりにくいです。

同様の完全一致報告は見つかりませんでしたが、OpenCode Go の利用制限まわりは、公式ドキュメント、GitHub issue、Reddit でもたびたび話題になっています。今後も同じ挙動が続くなら、スクリーンショットを時系列で残したうえで、OpenCode 側に問い合わせるのが一番確実です。
