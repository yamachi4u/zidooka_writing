Codexを使っていると、よく使う作業ディレクトリや定型作業を短い言葉で呼び出したくなります。

たとえば、`AGENTS.md` に「この言葉が来たら、このディレクトリで作業する」と書いておけば、エージェント側の運用ルールとしてはかなり便利です。

では、`/custom` のような独自スラッシュコマンドを自分で登録できるのでしょうか。

結論からいうと、少なくとも通常の `AGENTS.md` 運用では、任意のスラッシュコマンドを追加登録することはできなさそうです。

:::conclusion
`/custom` のようなスラッシュコマンドは、エージェントに届く前にCodex側のUIやCLIで先に解釈されます。そのため、`AGENTS.md` に書いても独自コマンドとしては動きません。
:::

## なぜAGENTS.mdでは登録できないのか

`AGENTS.md` は、エージェントが会話を受け取ったあとに参照する運用ルールです。

一方、スラッシュで始まる入力は、エージェントに渡される前の段階で、アプリ側のコマンドとして処理されます。

そのため、未定義のスラッシュコマンドを入力すると、エージェントが「その文字列を見て判断する」前に、UI側で「未対応のコマンド」として扱われます。

つまり、処理の順番はおおまかに次のようになります。

:::step
1. ユーザーが `/custom` のように入力する
2. Codex側のUIやCLIがスラッシュコマンドとして先に解釈する
3. 対応していない場合は、その時点でエラーになる
4. エージェントには通常のテキスト指示として届かない
:::

このため、`AGENTS.md` に「`/custom` と言われたら何かする」と書いても、実際にはその指示まで到達しません。

## できること: 通常テキストのショートカット

独自スラッシュコマンドは難しそうですが、通常のテキストとしてのショートカットなら運用できます。

たとえば、次のようなルールです。

```markdown
## Directory Shortcuts
- If the user says `project-a`, use `C:\path\to\project-a` as the default working directory.
```

この場合、`project-a` はスラッシュコマンドではなく、ただの会話文としてエージェントに届きます。

エージェントは `AGENTS.md` を読んだうえで、「この言葉はこのディレクトリのことだ」と解釈できます。

:::note
独自の短縮語を作るなら、スラッシュで始めず、普通の単語や日本語の合図にするのが現実的です。
:::

## できないこと: UI側コマンドの拡張

`AGENTS.md` はエージェントの振る舞いを調整するためのファイルであり、Codex UIやCLIそのもののコマンド一覧を増やす仕組みではありません。

そのため、以下のような用途には向きません。

- 新しい `/xxx` コマンドを追加する
- 既存のスラッシュコマンドの動作を上書きする
- 未定義スラッシュコマンドをエージェントに通常テキストとして渡す

これらは、UIやCLI側に正式な拡張機能が用意されていない限り、ユーザー側の `AGENTS.md` だけでは実現できないと考えたほうがよさそうです。

## 実用的な代替案

実用上は、次のような運用が扱いやすいです。

:::example
`project-a行って`、`原稿フォルダへ`、`請求書作業` のように、スラッシュを使わない短い合図を登録します。
:::

この方法なら、エージェントに自然言語として届きます。

また、作業ディレクトリだけでなく、次のような運用ルールにも使えます。

- 特定プロジェクトのデフォルトディレクトリ
- いつも読むべきメモや日報ファイル
- 投稿・公開・検証などの定型ワークフロー
- Gitを使うか使わないかの方針

重要なのは、スラッシュコマンドとしてではなく、エージェントが読める「普通の合図」として設計することです。

## まとめ

Codexで独自スラッシュコマンドを登録したくなる場面はあります。

しかし、`/custom` のような入力はUIやCLI側で先に処理されるため、`AGENTS.md` に書くだけでは独自コマンドとして使えません。

:::conclusion
任意のスラッシュコマンド登録はできなさそうです。代わりに、スラッシュなしの短縮語を `AGENTS.md` に登録して、エージェント側の運用ルールとして使うのが現実的です。
:::
