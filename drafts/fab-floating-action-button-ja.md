:::conclusion
FABは「1ページに1つの主役アクション」を、常に手の届く場所に置いておくボタンです。便利な反面、乱用すると画面の邪魔になります。導入前にチェックリストで判断しましょう。
:::

## FABとは何か

FABは Floating Action Button（浮動アクションボタン）の略です。画面の右下あたりに丸いボタンがポツンと浮かんでいて、タップすると主要アクションが動き出す、あのUIです。Google の Material Design で定義されたコンポーネントで、今では iOS アプリや Web サイトでも普通に見かけます。

ここで大事なのは、FABが飾りじゃない点です。ページで一番やってほしい動作を、指を伸ばせば届く位置に置き続ける仕組みです。どんなページでも似合うわけではなく、役割がはっきりしているからこそ生きるデザインです。

私もスマホアプリのUIを見るときに、FABがあるかないかで迷い方が違うなと感じます。何をしてほしいのかが、ボタン一つで決まる気がします。

## メリット

FABの強みは、主に4つです。

- 主要アクションへの導線が常に見える
- 親指リーチ圏内に置ける（モバイル）
- スクロール位置に関係なくアクセスできる
- ページの流れを邪魔しにくい

読み手を誘導したい動作が一つに絞れているページなら、この4つの効果は大きいです。コンテンツを読み終えて「さあ、次はこの動作」という瞬間に、同じ位置でボタンが待っています。

## デメリット

一方で、いい話ばかりでもありません。

- 画面の一部を常時占有する
- 誤タップ・意図しないタップが起きる
- アクセシビリティ配慮が必要（画面リーダー・コントラスト・大きさ）
- アクションが1つに絞れないページでは混乱する
- 過剰使用で逆効果

特に気になるのが誤タップです。親指が届きやすい位置は、うっかり押しやすい位置でもあります。削除や送信のような破壊的な動作をFABに割り当てるなら、確認ダイアログを挟みましょう。

:::note
ボタンには `aria-label` で役割を伝えます。アイコンだけのボタンは、画面リーダーでは何も伝わりません。
:::

## 実装パターン

Webでの実装は、CSSの `position: fixed` と `z-index` がベースです。そこに少しJavaScriptを足すと、いろいろな形に発展させられます。

### 基本形

```css
.fab {
  position: fixed;
  right: 16px;
  bottom: 16px;
  z-index: 100;
  width: 56px;
  height: 56px;
  border-radius: 50%;
}
```

`z-index` が効かないときは、親要素の `position` や `z-index` を疑いましょう。重なりの原因は、たいていそこで作られるスタッキングコンテキストです。

### スピードダイヤル

FABをタップすると、子ボタンが扇状に展開するパターンです。子ボタンが2〜3個ならシンプルにまとまります。5個を超えると、逆に操作が複雑になります。

### スクロール連動

下スクロールで表示、上スクロールで隠す、という挙動です。長い記事の途中でFABが残っていると邪魔なことがあります。条件付きで出し入れできると親切です。

### バッジ付き

未読数などの数字をFABに重ねるパターンです。通知の存在を常に伝えられます。ただ、数字が変化し続けると目が疲れるので、ほどほどにしたいところです。

### ラベル表示

アイコンだけでは意味が伝わりにくい場合、ラベルを付けます。広い画面では常時表示、狭い画面では長押しで表示、という出し分けがよく使われます。

### 拡張FAB

アイコンとテキストが横に並んだ「拡張FAB」もあります。主役アクションの意味を、初見で伝えたい場面に有効です。

## 具体例

よく見かける例を挙げます。

- Gmail：右下の作成ボタン
- Google マップ：経路ボタン
- Instagram：投稿ボタン

どの例も「この画面で一番やってほしい動作」が一つに絞られています。逆に、FABが複数並んでいる画面は珍しいはずです。この「1画面1 FAB」の原則が、実は一番大事です。

## 導入判断チェックリスト

導入前に、次の4つを確認します。

| チェック項目 | 確認ポイント |
| --- | --- |
| 主役アクションが1つ | このページで一番やってほしい動作は絞れるか |
| 親指リーチ圏内 | 右利きなら右下、左利きなら左下。届く位置か |
| モバイルが主 | スマホでの利用が中心か。デスクトップ中心ならヘッダーのボタンで十分 |
| 表示が邪魔にならない | コンテンツと重なる位置に常時出しても問題ないか |

一つでも「No」が出たら、別の形を考えたほうがいいです。普通のボタンや冒頭のCTAで十分なケースは少なくありません。

:::step
迷ったときの手順。まず主役アクションを1つ決めます。次にモバイルでの配置を決めます。最後に「常時表示でも邪魔にならないか」を実機で確認します。
:::

## まとめ

FABは便利なUIですが、過剰に使うと逆効果です。FABは「1ページに1つの主役アクション」を支える道具です。そう覚えておけば迷いません。
